# 事件编写最佳实践

## Note（备注）的使用

默认不使用事件编辑器顶部的 Note。它通常用于插件标签，不用于普通说明、开发记录或对话内容。

- 新建事件：保持 `note=""`。
- 修改已有事件：保留原有 note，不擅自覆盖或清空插件标签。
- 只有明确的插件要求或用户指定的特殊用途，才编辑 note；标签语法以项目插件为准，不编造标签。
- 需要解释事件逻辑时，使用指令列表中的 `Comment`。

这里的 Note 对应 `MapEvent.note`，属于整个事件，不是各事件页独立的字段；不限制 `Comment` 指令的正常使用。

## 一次性流程与完成后的事件页

拾取关键道具、首次对话、仅发生一次的事件，默认使用独立开关 A 记录该地图事件已完成。

- 主事件页：先执行全部流程，最后调用 `SetSelfSwitch("A", on=True)`。不能在发放道具或剧情完成前标记完成；确保执行路径能够到达该指令。
- 完成页：新建页或使用已有合适页面，页码必须大于主事件页，并用 `page.set_conditions(self_switch="A")` 设置 A=ON 为出现条件。引擎优先使用满足条件的最高编号页。
- 完成后隐藏：完成页不设图像、指令留空，使用人物下方优先级和确定键触发，避免留下阻挡或自动执行。
- 首次对话后仍需交互：完成页保留 NPC 图像和必要设置，内容改为再次对话，不重复执行首次流程。
- 检查其他高编号页及完成页的附加条件，避免被另一页覆盖或因多余条件无法接管。若 A 已有用途，先核对现有逻辑，不覆盖其含义。

独立开关按地图 ID、事件 ID 和字母区分，在当前存档中保持，离开地图再回来不会自动清除。它不跨不同事件共享；若多个地图事件需要共用同一完成状态，使用普通开关。`EraseEvent()` 仅暂时消除，不能替代一次性完成标记。公共事件中操作独立开关需要正确的地图事件调用上下文。

## 事件命名

地图事件使用简短、能说明用途的名称，例如“门卫”“宝箱”“入口传送”，不要求添加 ID 和类别前缀。

公共事件按游戏语言命名：中文使用 `事件ID:【类别】事件名`，英文使用 `事件ID:<Category>Event Name`，类别括号为半角 `<` 和 `>`。

- ID 与实际公共事件 ID 一致，至少三位，不足三位补零；使用英文冒号 `:`，不加空格。
- 类别按主要用途选择，例如功能、系统、剧情、音效、色调、物品、并行等，不限于这些类别。
- 事件名简短说明用途。

示例：

```text
138:【功能】启用灯光
001:【系统】初始化游戏
256:【剧情】第一章序幕
```

英文游戏示例：

```text
138:<Function>Enable Lighting
001:<System>Initialize Game
256:<Story>Chapter 1 Prologue
```

新建或按用户要求重命名公共事件时遵守此格式。复制到其他 ID 时同步调整名称中的 ID；仅修改既有事件指令时，不擅自批量重命名其他事件。公共事件名称通过数据库正式脚本修改，不能直接编辑 JSON。

## 公共事件列表分隔

左侧列表以 20 个半角 `-` 的显示宽度为排版参考。分隔名称用短标题居中、两侧补 `-`，例如：

```text
--------开场--------
```

这是显示宽度参考，不要求标题与横线合计恰好 20 个字符。分隔行属于功能区标题，可不使用普通公共事件的 ID／类别命名格式。

- 仅在划分游戏不同大功能区时少量使用，不为每个事件或小分组添加分隔。
- 例如 1–100 安排游戏系统相关事件，900–1000 安排小游戏事件，可在这些区段边界设置分隔。区间仅为示例，优先遵守工程已有分配，不据此自动移动或重编号。
- 使用专门的空公共事件作为分隔，指令列表留空（保留引擎结束标记），触发方式设为无；不要覆盖已有功能事件或被引用的事件。

## 临时图片与渐显渐隐

临时性图片使用完成后必须调用 ErasePicture 消除。透明度设为 0 只是隐藏，不能替代消除；提前结束或分支退出的路径也要完成图片清理。

渐显渐隐按以下顺序编写，始终使用同一个图片编号：

1. ShowPicture：初始 opacity=0。
2. MovePicture：设置渐显 duration 和目标 opacity=255，wait=True。
3. Wait：保持显示指定帧数。
4. MovePicture：设置渐隐 duration 和目标 opacity=0，wait=True。
5. ErasePicture：渐隐完成后消除图片。

opacity 范围为 0–255；渐显默认以 255（完全不透明）为目标。

仅改变透明度时，两次 MovePicture 都要显式保持图片原有的 x/y、origin、scale_x/scale_y 和 blend，避免默认参数导致图片移动、缩放或混合效果变化。渐显完成后再计保持时间，渐隐完成后再消除，不能在渐隐开始后立即消除。

## 一次性物品拾取

一般物品或没有对应贴图的物品，使用工程已有的闪光点行走图，例如名称含 sparkle 或 light 的素材；名称只是查找线索，需核对实际动画帧、角色索引和朝向。

- 第 1 页：walking=False、stepping=True，站立时循环播放闪光动画；自主移动保持固定，优先级通常为 below（角色下方）。默认 action，角色站到物品上按确定键拾取。
- 指令顺序：ChangeItems 增加物品 → SetSelfSwitch('A')；先发放，再标记已拾取。
- 后续更高编号页：出现条件为独立开关 A，图像和指令留空，优先级 below，触发方式 action。

参考[从创建事件开始的示例](../examples/one_time_pickup.py)。

## 门事件

命名为 `门（目的）` 或 `Door（目的）`，例如 `门（商店）`、`Door（Shop）`。

- 默认确定键交互（action），与角色相同优先级（same），自主移动固定。
- 关闭 walking、stepping 和初始 through，开启 direction_fix，避免交互时门自动转向。使用方向行表示开门阶段的门素材，初始 down 为关闭状态；索引和帧布局需核对素材。
- 流程：播放开门 SE → 本事件临时关闭固定朝向、转左、等待 3 帧、转右、等待 3 帧、转上、恢复固定朝向、开启穿透 → 玩家前进一步（跳过受阻、等待完成）→ 播放传送 SE → 传送玩家。
- 转向用于显示开门动画，不是让门移动；门路线等待完成；只在动画期间解除 direction_fix，动画后恢复。
- 从门正面交互，并核对传送落点。跨地图重新进入时门恢复初始状态；同地图传送应补充关门与关闭穿透，避免门持续敞开。

参考[门事件示例](../examples/door.py)。

## 事件图像动画

- 灯台、书、盆栽等没有转向动画的物件事件，应开启 direction_fix（固定朝向），避免交互时自动面向玩家而切换到错误的方向行。是否固定朝向按素材用途判断；只有需要转向动画的事件才关闭。固定朝向可以与 stepping 同时开启，用于固定方向的循环动画。
- 转向常用于切换动画阶段：把不同阶段画在行走图的不同方向行，通过 Route.turn 切换。相邻阶段一般间隔 Route.wait(3)，即 3 帧；可按素材节奏调整。方向对应的阶段以实际素材为准，不能把普通角色的转向默认当作动画。
- 使用转向动画期间关闭 direction_fix；门等平时需固定朝向的物件，在动画后恢复固定朝向；不希望常规步行动画干扰时关闭 walking。需要后续指令等动画结束时，SetMovementRoute 设置 wait=True。
- stepping 用于站立时循环播放当前方向行中的图案帧，例如闪光点、火焰。此类静止循环动画通常 walking=False、stepping=True，自主移动保持 fixed；踏步不会让事件来回走动，也不会自动切换方向行。
- 转向动画的 3 帧间隔由 Route.wait 显式控制；踏步动画的播放速度受引擎动画计时和移动速度设置影响，不能认为勾选 stepping 就是每 3 帧切换。

按需选择：一次性或分阶段动画使用转向与等待；持续循环动画使用踏步。制作前核对素材的角色索引、方向行和图案帧布局。

临时图片流程参考[图片示例](../examples/picture.py)，可调整图片、编号、位置、目标不透明度及三段时长；从 inspect 快照生成追加计划。

## 物品使用公共事件

由物品使用触发的公共事件，默认不再判断触发物品的持有数量：没有该物品时无法通过物品菜单触发。有效性检查针对点位、机关状态及额外使用条件，不重复检查触发物品库存。只有明确允许其他入口调用、且用户要求时，才另加库存校验。

物品效果登记调用该公共事件，公共事件按物品命名，沿用 ID／类别规范，例如 `138:【物品】旧钥匙` 或 `138:<Item>Old Key`。

1. 外层 IF 判断正确地图、位置、朝向及目标事件，成立分支中处理有效性与成功流程。用途宽泛时按需求省略位置限制。仅检查 y 和朝向不能证明正对指定事件，还需核对目标事件位置。
2. 正确位置内依次检查一个或多个使用条件，例如开关是否为 OFF。一般失败直接 JumpToLabel 到失败标签；需要特殊引导时显示提示后 ExitEvent，不再显示一般失败提示。
3. 全部条件满足后，按需扣除物品，再执行成功提示和演出。成功流程留在外层 IF 的成立分支内，分支自然结束，无需额外 ExitEvent。
4. 外层 ELSE 中按顺序判断特殊误用位置，每个特殊处理提示后 ExitEvent。可叠加多个特殊处理。
5. ELSE 中的特殊处理之后放 Label（例如 `Use Fail`），然后显示一般失败提示或调用提示公共事件。成立分支中的失败判断直接跳到这里，跳过特殊误用判断。标签只在当前列表内跳转，同名标签应唯一。
6. 示例中的 `//` 开头说明转换为 Python `#` 注释，不编译成 RM Comment 指令；用于事件分段的普通注释在示例中按参考案例保留。实际编写时必须按具体交互对象或情境改写，例如“对书架使用”“对锁住的门使用”，不要照抄“对【特殊事件】使用”等模板占位文字；提示和演出占位文字同样需替换。

若要失败不消耗、成功才消耗，物品数据库的 Consumable 必须设为 No，由成功分支 ChangeItems 扣除；否则引擎在公共事件执行前已自动消耗，不能再次扣除。地图使用物品通常将 Occasion 设为 Menu Screen，避免战斗中进入地图判断。物品效果注册、消耗性和可用场景通过数据库正式脚本配置。

参考[物品使用公共事件示例](../examples/item_common_event.py)。示例按公共事件 1204 的嵌套结构编写；按实际物品调整位置、开关、是否扣除及成功流程。

## 标签命名

标签使用简短、可读的自然语言，可用中文，例如 `使用失败`、`使用成功`。英文首字母大写，单词之间用空格，不使用下划线或连字符，例如 `Use failed`、`Use successful`。Label 与 JumpToLabel 必须使用完全相同的名称，同一指令列表中标签名应唯一。修改已有标签时同步更新对应跳转。

## 上锁的门

条件简单时优先使用事件页 conditions，不必在指令中重复嵌套判断。

- 第 1 页无出现条件：固定朝向，提示门锁着、需要钥匙。
- 钥匙使用成功的流程开启该门的解锁开关；仅持有钥匙不自动视为解锁。
- 第 2 页以解锁开关 ON 为出现条件，执行正常开门动画和传送；使用较高页码覆盖锁门页。
- 其他剧情限制按实际需要增加更高优先级页面，不机械照搬参考事件的所有页。

参考 Veloria Map005 事件 001：第 1 页锁门提示，固定朝向；第 2 页由开关 30 控制，播放开门流程；第 3 页由开关 247 控制其他提示。参考第 2 页未固定朝向，示例按当前约定改为平时固定、动画期间临时解除。开关编号、提示和目的地按实际游戏选择。
