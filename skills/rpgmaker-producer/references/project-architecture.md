# RPG Maker 项目架构

记录 RM 游戏工程的组织约定，覆盖地图、数据库等架构；不是技能仓库的软件架构。按用户讨论逐步补充，当前先确定地图的系统分区。本文用于设计与组织工程，不意味着自动创建或重组现有地图。

## 地图架构

### 地图设计与架构交付

项目默认采用箱庭式地图设计：围绕整体空间组织探索、逐步开放、连接、捷径与回访。多个角色里世界可共同组成一个大箱庭，玩家依次经历各分区，区域之间的连接和回访围绕整体设计；不用为每个角色强行建立互相隔离的完整循环。

即使暂时无法绘图，也应交付具体地图名称、地图树、实际连接关系和各地图职责。地图树表示工程组织，实际连接表示传送与空间关系，分别说明。地点、角色经历和地图数量结合用户需求确定；10–15 张只是此前示例的需求，不作为通用固定数量。名称按[命名规则](naming-rules.md#地图命名)选择具体地点或角色经历，如「Ethan的记忆」。

### 系统地图分区

创建一张名为「系统」的地图，作为地图树中的父级，集中容纳所有与系统相关的地图。这里用一张实际地图承担分组作用，不是文件系统目录。

```text
系统
├── 测试
├── 事件库
├── 游戏结束
├── 标题（事件标题）
└── 入口点
```

上述子地图分别承载测试、事件库、游戏结束、事件实现的标题及游戏初始化入口。其他系统相关地图也归入此父级；具体地图内容按项目需求继续设计。

系统分区整体预留约 10 张地图的容量，包含已规划的系统用途，为后续扩展留出余量；不是在上述地图之外额外预留 10 张。数量可按项目需要调整，不固定具体地图 ID，也不因此自动创建空白地图或重编号已有地图。

### 事件库

「事件库」地图专为 `VisuMZ_1_EventsMoveCore.js` 的事件模板功能设置，集中存放供复制、替换与动态生成使用的模板事件。

按用户的工程约定，使用该插件前**必须先设置事件库地图并配置加载**。已有事件库时先复用。先通过插件技能的 `.manual()` 阅读 Event Template Settings 及所用操作的说明，再查询相关参数声明和当前值。

在 Event Template Settings → Preloaded Maps 中加入事件库地图的实际 ID，使插件预加载该地图。使用命名模板时，按帮助配置 Templates 的 Name、Map ID、Event ID；帮助说明模板中的 Map ID 也会自动加入预加载列表。实施后核对事件库 ID、模板引用和实际加载结果，再使用复制、替换或生成操作。

这是用户要求的统一工程前置约定；原版帮助中的预加载要求用于模板地图，不据此声称角色阴影等每个独立功能在技术上都依赖事件库。

### 入口点

「入口点」地图设为角色的默认开始位置，作为新游戏启动流程的统一入口。一般将首次开始游戏需要设置的内容集中编写为一个初始化公共事件，由入口点地图的事件调用；初始化公共事件放在系统事件预留区，名称遵循[命名规则](naming-rules.md)，例如 `【系统】初始化游戏`。

该初始化事件是可复用的统一入口。后续功能有初始化需求时，在这里补充相应设置或调用，避免为每个需求另建独立的入口。初始化逻辑较复杂时，可以另行封装为职责明确的公共事件，再由统一初始化事件调用。具体调用顺序按功能依赖确定。

初始化时使用 **Change Transparency → ON（更改透明状态 → 开启）**，让玩家角色在开场处于隐身状态，方便制作序幕。这里的 ON 表示开启透明。需要角色出场时再按剧情流程设为 OFF；具体出场时机结合序幕设计确定。

其余首次游戏设置按项目需要加入初始化事件，不自行补造默认开关、变量或道具。初始化完成后进入项目指定的后续流程，目标地图和执行顺序结合项目确定。

在已有工程应用时，先核对当前开始位置和启动流程，再按确认的方案调整。这里描述架构约定，不自动创建测试地图、测试事件，也不自动搬移已有地图。

## 数据库架构

### 公共事件

公共事件 ID **1–100（含两端）固定预留给系统事件**，其他用途不占用这一区间。其余区间的用途尚未确定，后续按需求补充。

公共事件数量不足时，直接将数据库的公共事件最大数量提高到 **1000**，不逐个小幅扩容。此调整增加公共事件容量，不改变已有 ID，也不将系统预留区扩大到 1000；系统专用区仍为 1–100。若现有上限已达到或超过 1000，不降低上限。实际扩容通过数据库技能的正式脚本完成。

公共事件的用途与封装范围遵循[事件制作指南](event-production.md#公共事件封装原则)。

此处规定实际数据库 ID 的分区；公共事件名称仍遵循[命名规则](naming-rules.md)，不添加编号前缀。已有工程若存在占用冲突，先核对调用引用并提出调整方案，不自动搬移或重编号。


### 变量

- **1–10**：通用临时值，名称依次为 `x1` 至 `x10`，用于其他临时计算或传递。
- **11–20**：专用临时值，用于坐标、条件等有明确用途的临时数据；各编号的具体用途和名称后续确定。

临时变量按调用流程复用，不作为剧情进度等长期状态存储。使用前核对并行事件、嵌套公共事件以及等待期间的读写，避免尚未使用完的值被其他流程覆盖。新增命名约定集中维护于[命名规则](naming-rules.md)。

## 区域 ID

区域 ID 一般用不到，默认不分配、不预留用途区间，也不为了架构完整而在地图上绘制标记。只有具体功能明确需要时，才检查现有占用并分配所需 ID。

脚步声默认使用区域 ID 作为材质标记，按用户习惯从 **131** 开始分配。使用 `GabeMZ_StepSound.js`，具体制作见[脚步声手记](../production-notes/how-to-add-footstep-sounds.md)。这是分配起点，不意味着自动占用 131 以上全部区域；先核对现有区域用途与冲突。用户准备无限图层素材时，另行讨论标记方案。

## 工程目录

完整目录树及素材用途见[项目目录架构](project-directories.md)。

RM 工程根目录作为 Git 仓库根目录。保留引擎的标准工程目录，不默认在仓库下再套一层 `main/`。

GSAP 等可通过插件加载流程接入的工具库放在 `js/plugins/tools/`。例如 `js/plugins/tools/gsap.min.js`；库文件在依赖它的游戏插件之前加载。其他目录组织后续继续约定。
