# 测试工具现有功能与完善顺序

核对日期：2026-10-13。依据随技能分发的 session.py、connection.py、playtest.py 与 Debug.js 实现；区分已有接口、历史验证和本次实测结果。

## 现有组成

| 组成 | 已有能力 | 当前边界 |
| --- | --- | --- |
| session.launch | 独立启动 NW.js，使用临时用户配置、本机调试端口，检查引擎就绪和 test 模式 | 需要指定工程与可执行文件；没有启动环境诊断报告 |
| 会话清理 | 成功或异常均关闭本次进程组／进程树，删除临时用户配置 | 工程临时副本与测试扩展不由 session 管理 |
| Game | 连接已有页面、查询命令与帮助、调用命令、截图、检查 Debug 接口 | 附加模式 close 只断开连接 |
| CDP | 标准库 HTTP／WebSocket，本机页面选择、Runtime.evaluate、任意 CDP 请求 | 单请求串行；事件只保留最近 200 条，未形成日志接口 |
| Debug 命令注册 | 注册、发现、帮助、参数校验、串行执行 | 命令名为字母开头的字母数字串，例如 roomSetup；参数目前主要支持 integer、minimum、required |
| 操作追踪 | running、succeeded、failed、unknown，保留运行中和近期完成结果 | 超时用 operation(id) 查询；结果 unknown 不表示操作未执行 |
| HUD | 显示场景、地图、坐标、方向及 FPS；回显 console 信息 | 输入框目前只回显文字，不执行命令；FPS 依赖引擎计数器 |

## 内置游戏命令

- `state`：场景名、地图 ID、玩家坐标、是否传送，以及 errorPrinter 中的错误文字。
- `loadGame(slot)`：按 Scene_Load 引擎流程读档，等待地图就绪；slot 为必填整数且 minimum=1，不等待地图开场事件执行结束。

其余游戏操作需要工程子插件实现。现阶段没有正式的新游戏、传送、玩家输入、事件交互、开关变量读写、保存测试存档、等待剧情完成或结果断言命令。CDP 底层可执行表达式不等于已经提供这些游戏测试接口。
